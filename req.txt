1. Overview

 - In this project, you will build a mini shell in C that can run common Linux programs such as ls, cat, grep, wc, sort, and echo. 
 - Your shell will create child processes with fork(), run programs with an exec family function, support input/output redirection, 
 - connect programs with pipes, and handle common terminal signals such as Ctrl+C.
 
 - This project is designed to help you understand how real shells work at a practical level. By the end, you should be able to 
 - explain how the OS launches programs, how standard input/output/error are redirected, how pipes connect processes, and how signals 
 - interact with foreground programs.
  
 - Your shell does not need to be as full-featured as Bash. The goal is a clean, correct, and understandable implementation of core Unix shell behavior.

    Your shell must support these redirections:

        Examples:

        - cat < input.txt
        - ls > out.txt

        - sort < in.txt > out.txt

        Requirements:

        * use open() and dup2()

        * truncate output files for > redirection
        * report errors when files cannot be opened

    E. Pipes
    Your shell must support pipe | between commands.

        Examples:

        - cat file.txt | wc -l
        - ls | sort
        - cat file.txt | grep hello | wc -l
        - Requirements:

        * support pipelines of at least 3 commands, not just one pipe
        * use pipe(), fork(), dup2(), and close() correctly
        * wait for all children in the pipeline

    F. Signal handling
    Your shell must handle Ctrl+C reasonably.

        Expected behavior:

        DONE * when the shell is waiting for input, pressing Ctrl+C should not kill the shell
        DONE * when a foreground child process is running, Ctrl+C should terminate the child process in the normal way

        A common design is:

        DONE * the shell process ignores or handles SIGINT
        DONE * child processes restore default SIGINT behavior before exec
        DPME * You do not need to implement full Unix job control.

    G. Basic syntax error handling
    Your shell should detect and report simple invalid input instead of crashing.

        Examples of errors:

        - missing filename after <, >, or 2>
        - pipe at beginning or end, such as | ls or ls |
        - repeated malformed operators such as ls >
        - You do not need to match Bash’s exact error messages, but your shell should print a clear error and continue running.
